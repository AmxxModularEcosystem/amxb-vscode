# Программный API путей инклюдов — контракт для `Faktor.amxx-pawn-all-in`

**Статус:** реализовано (All-In ≥ 1.13.0) · **Целевое расширение:** `Faktor.amxx-pawn-all-in` (VS Code Marketplace) · **Репозиторий:** `droads/VSC-Amxx-Pawn-All-IN`
**Версия контракта:** 1.0 (только аддитивные изменения)

> Реализация: `activate()` расширения возвращает `{ setIncludePaths, clearIncludePaths, getIncludePaths, getProgrammaticIncludePaths, onDidChangeIncludePaths }` (`services/programmatic-include-paths.js`). Данный документ остаётся эталоном семантики.

---

## 1. Назначение

Расширение разрешает `#include <...>`, обходя статические пути поиска, заданные в настройках VS Code
(`amxxPawnAllIn.projectLocalIncludePaths`, `amxxPawnAllIn.globalIncludePaths`), плюс пути,
авто-обнаруженные в корне проекта. Инструменты, которым известна *реальная* раскладка зависимостей
проекта (системы сборки, пакетные менеджеры, компиляторы, другие расширения), сейчас **не имеют
программного способа** внести директории инклюдов — единственный канал это запись в `settings.json`,
которая персистится, машинно-зависима и засоряет папку проекта.

Данный контракт определяет небольшой **runtime-only, in-memory** API, позволяющий любому инструменту
вносить пути поиска инклюдов в расширение **без изменения настроек VS Code и без записи каких-либо
файлов**.

## 2. Цели дизайна

- **Только на время выполнения.** Значения живут в памяти в течение жизни экземпляра расширения.
  Ничего не пишется в `settings.json` (ни в user-, ни в workspace-, ни в folder-scope) и не создаётся
  никаких файлов.
- **Мульти-контрибьютор.** Несколько инструментов (разные расширения, скрипты) могут вносить пути
  одновременно, не затирая друг друга. Каждый контрибьютор регистрируется под своим стабильным id.
- **Семантика replace для каждого контрибьютора.** Контрибьютор заменяет свой собственный набор
  целиком; вклады остальных не затрагиваются.
- **Определённый приоритет.** Программные пути ищутся **до** сконфигурированных `globalIncludePaths`
  и **после** project-local путей, чтобы инструмент, разрешающий реальные версии зависимостей, мог
  перекрыть устаревшие ручные глобальные пути.
- **Самовосстановление.** Несуществующие директории игнорируются в момент разрешения, так что
  контрибьютор может регистрировать пути, которых ещё нет (они будут подхвачены после
  материализации).
- **Универсальность.** API не привязан к инструменту: в поверхности нет ссылок ни на какую
  конкретную систему сборки или расширение. Принять его может любой консьюмер.
- **Толерантность.** Некорректный ввод игнорируется, не бросает исключений и не портит текущее
  состояние.

## 3. Поверхность API

Доступен через стандартный паттерн API расширений VS Code:

```ts
const ext = vscode.extensions.getExtension('Faktor.amxx-pawn-all-in');
const api = ext?.exports as IncludePathsApi | undefined;
```

```ts
/** Форма `exports` расширения `Faktor.amxx-pawn-all-in`. */
export interface IncludePathsApi {
  /**
   * Устанавливает (заменяет) пути инклюдов, вносимые контрибьютором `contributorId`.
   *
   * - Пути могут быть абсолютными или относительными к любой папке воркспейса.
   *   Порядок массива значим: первый элемент имеет наивысший приоритет.
   * - Директории, которых (пока) нет на диске, игнорируются в момент разрешения;
   *   они подхватываются, как только появляются.
   * - Пустой массив очищает вклад контрибьютора (аналог `clearIncludePaths`).
   * - Некорректные вызовы (пустой/пробельный `contributorId`, нестроковые элементы,
   *   не-массив `paths`) игнорируются.
   */
  setIncludePaths(contributorId: string, paths: readonly string[]): void;

  /** Полностью удаляет вклад контрибьютора `contributorId`. No-op, если неизвестен. */
  clearIncludePaths(contributorId: string): void;

  /** Пути, зарегистрированные контрибьютором `contributorId` (пустой массив, если их нет). */
  getIncludePaths(contributorId: string): readonly string[];

  /**
   * Все пути контрибьюторов в эффективном порядке поиска:
   * контрибьюторы в порядке первой регистрации, внутри каждого — порядок массива сохранён.
   */
  getProgrammaticIncludePaths(): readonly string[];

  /**
   * Срабатывает после любого изменения путей контрибьюторов (set/clear).
   * Слушателям следует перезапустить всё, что зависит от путей поиска инклюдов
   * (граф инклюдов, диагностику, completion, hover). Слушатель не получает
   * аргументов; текущее состояние запрашивается через `getProgrammaticIncludePaths()`.
   */
  onDidChangeIncludePaths(listener: () => void): vscode.Disposable;
}
```

## 4. Приоритет при разрешении инклюдов

От высшего к низшему (новый — только программный тир):

1. Кавычечный `#include "x"` — разрешается относительно включающего файла (без изменений).
2. Project-local пути — `amxxPawnAllIn.projectLocalIncludePaths` (без изменений).
3. **Программные пути контрибьюторов** — этот API (новый тир).
4. Сконфигурированные глобальные пути — `amxxPawnAllIn.globalIncludePaths` (без изменений).
5. Авто-обнаруженные источники в корне проекта (без изменений).

Внутри тира 3 приоритет следует порядку уплощённого списка контрибьюторов из
`getProgrammaticIncludePaths()` (порядок регистрации контрибьюторов, затем порядок массива внутри
каждого). Расширение может объединять тиры 3 и 4 в один упорядоченный список кандидатов при условии,
что элементы тира 3 всегда предшествуют элементам тира 4.

## 5. Семантика

- **Без персистентности.** Всё состояние — в памяти, в рамках экземпляра расширения, и теряется при
  перезагрузке extension host. API никогда не пишет в `settings.json` и ни в какие файлы.
- **На воркспейс.** Каждое окно VS Code имеет свой экземпляр расширения и, соответственно, своё
  состояние контрибьюторов. Регистрация ограничена текущим окном; один и тот же id контрибьютора в
  двух окнах независим.
- **Замена, а не слияние.** `setIncludePaths(id, paths)` заменяет весь набор для `id`. Чтобы изменить
  один путь, контрибьютор перерегистрирует полный новый список.
- **Идемпотентность.** Вызов `setIncludePaths` с теми же значениями не порождает события об изменении
  и не пересканирует (расширение должно сравнивать перед срабатыванием).
- **Валидация.** Некорректный ввод молча игнорируется; корректные вызовы всегда успешны и не бросают
  исключений.
- **События.** `onDidChangeIncludePaths` срабатывает синхронно после успешной мутации. Слушатели не
  должны синхронно мутировать API изнутри слушателя (при необходимости — `setImmediate` /
  `queueMicrotask`). Возвращаемый `vscode.Disposable` отписывает.
- **Консистентность.** При изменении эффективного программного списка расширение должно обновиться
  точно так же, как при изменении своих настроек путей инклюдов: сбросить кэши инклюдов, пересчитать
  граф инклюдов открытых документов, пересчитать диагностику/completion/hover.

## 6. Доступность и активация

- Консьюмеры получают API через `vscode.extensions.getExtension('Faktor.amxx-pawn-all-in')`.
- `exports` равен `undefined`, пока расширение не активировано. Консьюмер может вызвать
  `await extension.activate()` заранее, либо просто обработать `exports === undefined` (расширение не
  установлено / ещё не активировано), пропустив вклад.
- API должен быть выставлен из возвращаемого значения `activate()` (или присвоен `exports` во время
  активации) и оставаться стабильным в течение жизни расширения.

## 7. Пример (эталонный консьюмер)

```ts
import * as vscode from 'vscode';
import type { IncludePathsApi } from 'Faktor.amxx-pawn-all-in'; // или структурный тип

const ALL_IN_ID = 'Faktor.amxx-pawn-all-in';

async function contributeIncludePaths(dirs: string[]): Promise<void> {
  const ext = vscode.extensions.getExtension(ALL_IN_ID);
  if (!ext) return; // не установлено
  const api = ext.exports as IncludePathsApi | undefined;
  if (!api) await ext.activate(); // дождаться exports
  const ready = ext.exports as IncludePathsApi | undefined;
  if (!ready) return;
  ready.setIncludePaths('example-tool', dirs); // идемпотентная замена
}

function stopContributing(): void {
  const ext = vscode.extensions.getExtension(ALL_IN_ID);
  const api = ext?.exports as IncludePathsApi | undefined;
  api?.clearIncludePaths('example-tool');
}
```

## 8. Заметки по реализации (для мейнтейнера All-In)

- Хранить `Map<contributorId, string[]>` в settings-сервисе или соседнем модуле; порядок вставки в map
  — порядок приоритета контрибьюторов.
- `getProgrammaticIncludePaths()` = уплощение `[...map.values()]` в порядке map.
- Связать мутации с существующим refresh-пайплайном, который уже используется при изменении
  `amxxPawnAllIn.globalIncludePaths` (settings `refresh()` → сброс кэшей → пересчёт графа инклюдов →
  обновление диагностики/completion/hover), и срабатывать `onDidChangeIncludePaths`.
- Приоритет: собирать список путей поиска как `[project-local…, programmatic…, configured-global…]`
  до дедупликации; существующая дедупликация (`collectUniqueSources`) сохраняет порядок, так что
  больше ничего менять не нужно.
- Нигде не персистить map; не писать настройки.

## 9. Вне объёма

- Без файловых watcher'ов, без записи на диск, без записи настроек.
- Без гранулярности по файлам или расширениям сверх id контрибьютора (один набор на контрибьютора).
- Без удаления тиров project-local/global/discovered — этот API только добавляет новый тир.
- Не замена `amxxPawnAllIn.projectLocalIncludePaths` / `globalIncludePaths`; те остаются для ручной
  настройки.
